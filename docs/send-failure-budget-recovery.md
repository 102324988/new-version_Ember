# 消息回复失败：额度与后台重试修复

后续规则已改为[用户对话不限额、后台独立预算](model-budget-memory-reliability-delivery.md)。本文的每日总上限与临时 300 次是修复经过，不是当前前台限制。

日期：2026-11-10。

## 实际原因

只读核对服务、数据库及调用记录：发送的用户消息已经保存，失败发生在模型回复阶段。当天模型调用达到应用的 200 次限制，其中记忆整理失败调用 136 次；日志显示记忆请求反复超时。HTTP 就绪与数据库正常，并不能证明仍有模型额度。

此前后台整理和用户对话共用 20 秒请求超时，非流式记忆 JSON 需要等待完整结果；失败后工作线程每分钟重试，加上客户端立即重试，持续消耗每日额度。前端只显示笼统的轮次失败，一键诊断也没有查询应用的每日用量，未能指出这条业务故障。

## 修复

- 保留所有成功和失败调用记录，不重置计数。后台聊天调用最多占基础日额度的 75%，其余至少 25% 留给用户状态准备及回复；总额度仍是硬限制。临时追加额度不扩大后台预算。
- 记忆整理独立使用 `EMBER_MEMORY_REQUEST_TIMEOUT`（默认最多 60 秒），不再受对话首包 20 秒配置影响；取消整理请求的立即重试。
- 同一整理失败后按 60、120、240 秒逐步延长重试间隔，最多一小时，记录保存在工作记忆中。重启不能绕过退避；原始日志、中期记录和未完成入库任务保留。已有入库任务可以继续安全派发。
- 编码上下文不再每次重复附带全部缓冲和笔记；完整日志前缀仍保留，成功确认后才消费，不能靠截断或删除资料让错误消失。
- 额度、连接/超时、认证、供应商限流均映射为安全的公开错误，随轮次结束发到前端，不发送供应商原始异常或密钥。
- 一键诊断新增每日聊天、向量、语音用量，以及应用日志文件中的额度/超时分类。只读查询，不导出正文。

## 经用户同意的临时恢复

仅 **2026-11-10** 将聊天调用上限提高到 300 次，最多额外 100 次调用，保留既有计数。`deploy/service.env` 添加：

```dotenv
EMBER_CHAT_OVERRIDE_DATE=2026-11-10
EMBER_CHAT_OVERRIDE_LIMIT=300
```

按 Asia/Shanghai 的现实日期检查，次日自动回到基础 200 次，无需再启动脚本或清理数据库。原配置备份位于私有目录，不提交仓库。后台今天已超过新后台上限，不再挤占这 100 次追加额度；尚未整理的资料继续保留，后续有预算且退避到期后处理。

## 验证

独立 PostgreSQL 测试实例上的完整回归 374 项通过，新增用例覆盖后台预留、日覆盖失效、计数保留、跨重启退避、单独超时和前端安全错误；前端单元 32 项、lint 与生产构建通过。浏览器额外验证额度提示可见。没有用真实聊天作为自动测试输入。

修复已更新到本机容器。发布前恢复点为 `before-budget-fix-20261110-mpka1i`，旧镜像标签 `ember-service:before-budget-fix-20261110`。更新后大小模型各一次最小合成请求均成功，不生成语音、不写入聊天；这两次也计入用量，校验时为 202/300，原 200 次记录未改变。原有 63 条聊天内容哈希全部一致；一键诊断报告显示当前服务及额度正常，历史额度拦截仍作为提示保留。
