# 桌面稳定性迭代

本轮以正在使用的回退行为为基线。对话节奏试验、后台记忆修复、桌面范围调整是独立变化。默认保留原有对话表达、历史索引、场景证据优先级和状态更新频率。

## 异常复盘与对照

通过改版前后的消息指纹定位到三轮对话。在只读事务中核对前后相邻正文。改版期间的问题主要是没有接住用户的澄清请求，而是把更早、无关的课程话题拉回来，并突然告别。回退后的相邻两轮则能承接当前话题。这个窗口不能证明历史格式、状态视角或表达规则中哪一项单独导致问题。回归用合成情境表达同类断点，不保存或发送真实对话原文。

试验开关 `EMBER_DIALOGUE_RHYTHM=turn_v1` 只替换普通对白的自适应表达一段。主动对白、显式简短或详细偏好、旧版策略、场景提示、工具和历史不变。默认和回退均为 `EMBER_DIALOGUE_RHYTHM=baseline`。容器版的开关放在 `deploy/service.env`，本地开发放在 `.env`。只有部署本轮代码后开关才有效，可在 `/config` 的 `dialogue_policy.rhythm` 核对。

```powershell
python utils/compare_dialogue_expression.py --comparison rhythm
python utils/compare_dialogue_expression.py --comparison repeat --case clarify_without_old_topic --real-model --tag your-review
python utils/compare_dialogue_expression.py --comparison rhythm --case clarify_without_old_topic --case greeting_after_technical_topic --real-model --tag your-review
```

第一条只生成提示。带 `--real-model` 的命令使用现有在线模型，只发送合成数据；每个指定情境两次请求，默认最多两组。固定时钟后确认两份基线提示完全一致，表达对照仅有一段提示差异。小样本中有一次基线把澄清拉回旧技术话题，候选没有；问候样本中基线反而更短。先保持关闭，不能用这两个情境判定整体自然度。启用默认前要补多轮抽查和匿名人工评阅，覆盖题意、指代、时空、念出来的节奏、复杂解释和主动对话，语言表现不过关就不启用。

## 后台整理与流程观察

分批现在以实际 JSON 封装的保守字节估计为准，按完整日志行取前缀。单条过长则按可用空间拆分，保留来源 ID 和字符范围，全部完成后才确认父记录。预算数值未变，前台仍不受应用每日次数限制。失败待处理时，心跳不再反复解析整本积压日志；分批修订号变化允许已因配置失败的任务重新获得一次尝试。

上线后确认分批不再卡在 `input_budget`，累计完成多批，新增双向量记录并继续消化日志。校验时积压仍有约 1.1 MB，主要是旧角色状态，按现有后台预算继续，不能把“正在整理”写成“全已入库”。设置中的队列详情和 `diagnose.bat` 可用于检查。

在跟踪期间发现旧的睡眠衰减会以清晰度阈值硬删除长期记忆。现已改成衰减但保留记录，清晰度下限为 0.01。从本地同一世界的已校验存档补缺可使用 `utils/recover_missing_vectors.py`。默认仅预演，启用写入前备份当前世界，先核对条数，再传 `--apply --expect-missing <条数>`。按稳定 ID 仅插入，不覆盖现库，不改聊天、世界或中期待办。

已从同一世界的改版前和回退前两个存档补回 53 条。复查两份存档的稳定 ID 均已存在，现库共 87 条带向量长记忆。运行中的后台整理有 16 次已完成，最近没有留在退避状态，一次供应商输出截断已通过现有拆分路径继续处理。

应用日志可查看 `turn timings` 和 `speech timing`，分别记录场景准备、首段模型文本、工具和回复结束，以及语音排队与音频就绪。首段模型文本的时刻不是浏览器首字渲染时间。同轮时间相关信息取同一个逻辑时刻，历史入库和语音共用正文提取规则。普通回合仍做原来的场景准备，避免用话语长短推断场景不会变化。

## 桌面交付与共同活动

取消 Android 和双端同步草案及手机专用入口说明。设备会话、授权、窄桌面窗口、存档与聊天数据继续保留。桌面测试仍覆盖直接改场景、登录和会话撤销的相关路径。共同手册现在在暂停页显示停在哪一步、保留几份材料；讨论入口按当前步骤填入简短草稿，仍由用户自行发送。真正的选择和材料继续由程序规则提交。

隔离 Docker 测试库的后端回归 417 项和随后记忆定向 27 项通过。前端单元 32 项、五组桌面浏览器回归、lint 和构建通过；手册改动后另复查了暂停、刷新和续做。短时桌面连续验证运行 304 秒、59 条合成回复，始终一个角色画布，最多一路语音。部署镜像 `ember-service:desktop-verified-20261120` 通过就绪和桌面设置检查，97 条已有聊天逐条指纹一致，数据库容器未替换。恢复点为 `before-rollback-desktop-20261120-7dezdo`；回退镜像使用 `ember-service:before-desktop-retention-20261120`，除必要情况优先修复前进，因为旧镜像仍会删除低清晰度记忆。

最终镜像在本机独立 Compose 栈通过应用正常重启、进程崩溃自恢复、断库返回 503、重连、真实存读档和控制数据在空库逐表恢复。未模拟业务库故障。报告在 `output/service-verify/`。

多轮评估用三段合成情境，各走三个回合，覆盖澄清、跨日返回与复杂解释。最终不另限输出长度的 18 条回复全部正常结束，候选能接住澄清、解释完整，但跨日讨论更冗长，也没有稳定优势，默认仍为 `baseline`。评阅材料在 `output/dialogue-expression/desktop-final-blind/blind-review.md`。

本轮接受本机工程验收。真实用户的自然度偏好和隔日可玩性仍需按[试玩任务卡](usability-study.md)收集。独立常开设备确定后再实施 72 小时持续服务和异机恢复。
